# Canadian Lakes Public Plow Tracker

A standalone, public, **live** plow tracker for Canadian Lakes, Michigan —
built outside Muse so drivers can open it in a normal browser from a
textable link, and Grayson can still watch all three trucks live.

**Why this is a separate app:** a public page inside Muse is static — it
has no server, so it cannot relay live GPS positions or sync road
completions between phones. The Muse live tracker is account-tied and has
no public link. This app has its own small server, so it can do both.

## What it does

- **v11 routes, exactly:** 165 roads, 47.4 mi — Red Single Axle 73 roads /
  22.5 mi / ~151 min, Orange Single Axle 56 roads / 19.1 mi / ~160 min,
  Backhoe 36 roads / 5.75 mi / ~52 min. Geometry is copied from the
  verified v11 data (`public/routes.json`, regenerated by
  `scripts/extract-routes.py` — it matches the v11 CSV exactly).
- **Live, no reload:** driver phones send GPS every ~3 seconds; the server
  pushes positions and completions to every open admin/driver screen over
  Server-Sent Events. Truck pins glide between updates; road colours
  change in place.
- **Progressive green + end-to-end completion, same as the Muse tracker:**
  each road is split into ~20 m sections. As the truck drives, the sections
  it has actually passed turn green on the map, section by section — so
  turning off mid-road leaves only the driven part green. A road still
  counts DONE (and turns fully green) only once the truck's GPS has come
  within 45 m of **both** ends of the road **and** covered at least 80%
  of its ~20 m sections. Both ends alone is not enough — a road's ends
  sit on other roads, so driving those can hit both ends without ever
  driving the road itself (Deerfield Road was falsely marked done at
  38% covered on 2026-11-23). Loop roads need the start plus
  the far side of the loop. Drivers can also tap a road to mark it done
  by hand.
- **Any truck can do anybody's road:** if a driver ends up on another
  truck's route and actually drives that road — both ends and at least
  80% of it — it turns green for everyone (admin, the road's own truck,
  and the helper). Just passing its ends does not count it done.
- **Follow mode:** on a driver link, tapping Start GPS tracking also
  turns on follow — the map pans to keep the truck centred, so no
  manual zooming/panning while driving. Dragging the map pauses
  follow; the "Follow my truck" button turns it back on.
- **Breadcrumb trail:** every GPS fix also leaves a black dotted trail,
  on a route road or not — so if a driver takes an extra
  road that isn't on the map, the trail still shows exactly where they
  went. A parked truck doesn't pile up points (only moves over 10 m
  are added, capped at 2,000 points per truck per run). Admin sees all
  three trails; a driver sees only their own.
- **Drive it your way:** drivers do roads in any order; the list order is
  only a suggestion.
- **Driver-only links:** `?driver=1&truck=1` (Red), `?driver=1&truck=2`
  (Orange), `?driver=1&truck=3` (Backhoe) lock that phone to one truck —
  no admin view, no truck switcher. The admin view (plain link, no
  `?driver=1`) shows all three trucks live.
- **Markers:** Red starts Buchanan & Highland Trail, Orange starts
  Buchanan & East Royal Rd, Backhoe starts Buchanan & West Royal Rd.
  Sand pile at the dead-end turnaround on Seven Mile Rd by 100th Ave;
  HOME at the barn, NE corner of 150th Ave & 12 Mile Rd.

## PINs — change these before sharing

Every truck has a PIN, and the admin has a PIN. A position or a manual
mark is only accepted with the PIN for that truck; live positions are
only served to the admin PIN (all trucks) or a truck PIN (its own truck
only). No PIN = routes and map only, no live data.

**Defaults (change them — see Deploy below):**

| Who | PIN |
|---|---|
| Red Single Axle (Truck 1) | `1101` |
| Orange Single Axle (Truck 2) | `2202` |
| Backhoe (Truck 3) | `3303` |
| Admin (Grayson — all trucks + reset) | `9999` |

Set them with environment variables `TRUCK1_PIN`, `TRUCK2_PIN`,
`TRUCK3_PIN`, `ADMIN_PIN` (see `.env.example`). On Render they are set
in the dashboard; the included `render.yaml` generates random ones —
copy them from the dashboard and give each driver only their own.

> These are simple 4-digit codes, not bank-grade security. They stop a
> random person with a forwarded link from watching the trucks or faking
> positions, but anyone Grayson tells a PIN to can use it. If a PIN leaks,
> change it in the hosting dashboard and re-share that truck's link.

## How it works (tech, in one paragraph)

Zero-dependency Node.js (Node 20+), no build step, no database to set
up. `server.js` serves the frontend from `public/` and keeps the current
run in memory + `data/state.json`. Positions arrive at
`POST /api/position`, completions are computed server-side, and every
connected browser gets the new state instantly over `GET /api/events`
(SSE). The map is Leaflet with OpenStreetMap tiles (loaded from a CDN,
so drivers need mobile data — same as any map app). One server instance
is the source of truth, so all three trucks stay in sync.

## Try it locally

```bash
cd canadian-lakes-plow-public-tracker
node server.js            # http://localhost:3000
npm test                  # end-to-end tests (routes, PINs, end-to-end rule, SSE, reset)
```

Then open `http://localhost:3000/?driver=1&truck=2`, enter PIN `2202`,
tap **Start GPS tracking**. To watch a simulated drive without a truck:
`node scripts/simulate.js http://localhost:3000 2 2202 "Valley Court"`
— it drives Orange down Valley Court and back, 3 seconds a step, and
the admin view (open `http://localhost:3000/`, PIN `9999`) should show
it go amber, then green.

Note: phone GPS (`navigator.geolocation`) only works on HTTPS pages or
`localhost`. The hosted deploys below all give you HTTPS automatically.

## Deploy — option 1 (recommended): Render, free tier

No credit card needed for the free tier. You need a free Render account
and a GitHub account to hold the code.

1. Put this folder in a GitHub repo (e.g. `canadian-lakes-plow-tracker`).
   If you don't have git set up, in this folder: `git init`, `git add .`,
   `git commit -m "Public plow tracker"`, create the repo on GitHub, then
   `git remote add origin <repo URL>` and `git push -u origin main`.
2. In Render: **New > Blueprint**, pick the repo. Render reads
   `render.yaml` and creates the web service.
3. In the Render dashboard for the service, open **Environment** and
   note the four generated PINs (`TRUCK1_PIN`, `TRUCK2_PIN`,
   `TRUCK3_PIN`, `ADMIN_PIN`). Change them to codes you'll remember,
   or keep the generated ones — either way, write them down.
4. Wait for the deploy to finish. Render gives you a URL like
   `https://canadian-lakes-plow-tracker.onrender.com`.
5. Your links (replace the domain with yours):
   - Admin (Grayson): `https://<your-app>.onrender.com/`
   - Red driver: `https://<your-app>.onrender.com/?driver=1&truck=1`
   - Orange driver: `https://<your-app>.onrender.com/?driver=1&truck=2`
   - Backhoe driver: `https://<your-app>.onrender.com/?driver=1&truck=3`
   Text each driver their link **plus their PIN only**.
6. Test it: open the admin link, enter the admin PIN, then open a
   driver link on another phone (or the simulate script) and watch the
   pin move and a road go amber, then green.

**Free-tier caveats (honest):** the free service sleeps after ~15 minutes
with no visitors, so the first load after a quiet spell takes ~30–60
seconds to wake up. During a storm, once anyone has it open it stays
awake. The free disk is also ephemeral: if Render restarts or redeploys
the service, the current run resets to 0 done (routes are unaffected —
they're in the code). If that matters, Render's $7/month Starter plan
keeps it awake and lets you attach a persistent disk (set `DATA_DIR` to
the disk mount path).

## Deploy — option 2: Fly.io

Needs a Fly.io account and `flyctl` installed. It does not sleep like
Render's free tier, but Fly asks for a card on file.

```bash
fly launch --no-deploy   # accept the settings in fly.toml
fly secrets set TRUCK1_PIN=1101 TRUCK2_PIN=2202 TRUCK3_PIN=3303 ADMIN_PIN=9999
fly deploy
fly open                 # shows your https://<app>.fly.dev URL
```
Links are the same shape as above, with the `.fly.dev` domain.

## Deploy — option 3: Docker / any VPS

```bash
docker build -t plow-tracker .
docker run -d -p 3000:3000 \
  -e TRUCK1_PIN=1101 -e TRUCK2_PIN=2202 -e TRUCK3_PIN=3303 -e ADMIN_PIN=9999 \
  -v plow-data:/app/data --name plow-tracker plow-tracker
```
Put it behind HTTPS (e.g. Caddy/Nginx) — phone GPS will not work over
plain HTTP on a public host.

## What was verified here (and what was not)

Verified locally, 2026-11-22 (`npm test` — all 9 checks pass, plus a
live smoke test on port 3456):
- 165 roads load, 73/56/36 per truck, miles 22.51/19.11/5.75, matching
  the v11 CSV exactly (name/order/truck, zero mismatches).
- PINs enforced (401 with no/wrong PIN); a truck PIN sees only its own
  truck, admin sees all three.
- End-to-end rule: Montreal Lane went amber at one end, green only at
  both ends; Orange driving at Red's road ends did not complete it.
- SSE stream delivered a new position to a connected admin client
  without a reload; manual mark-done/undo and admin reset work.
- Live smoke test: Valley Court (Orange) went amber then green on the
  real server, and the state file persisted it.

NOT verified (needs a real deployment + a real phone):
- A public URL (nothing is deployed yet — see above).
- GPS tracking from a moving phone, the Leaflet map tiles on a driver's
  phone, and the pin glide at road speed. The map tiles come from
  OpenStreetMap's public tile server via the Leaflet CDN; if a driver
  has no data signal, the map won't load (the road list still works).
- Behaviour under three phones sending at once for a whole storm
  (in-memory state + one Node process is fine for three trucks, but it
  has not been load-tested beyond that).
